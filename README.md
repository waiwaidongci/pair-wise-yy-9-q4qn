# 玻璃板回收与二次涂布准入台

古法蓝晒玻璃板的旧底片回收登记、清洗准入、二次洁净确认与涂布槽调度。

## 运行

```bash
npm start          # http://localhost:3040
npm test           # 业务规则端到端测试
```

数据保存在 `data/glass-plate-recovery.json`（首次启动自动生成种子数据）。
可用 `GP_DB_FILE=xxx.json` 覆盖数据文件名，`PORT=xxxx` 覆盖端口。

## 业务流程

1. **玻璃板建档**：编号、尺寸、来源批次、备注。
2. **旧底片交付登记**：登记划痕判定、乳剂残留判定、清洗人。
   - 划痕或乳剂残留任一不合格 → 状态「待复洗」，只能复洗后重新交付，**不能占用涂布槽**，也不允许做洁净确认。
3. **回用前洁净确认**：由**清洗人之外的另一人**，对表面洁净**连续确认两次**，两次间隔**满四小时**。
   - 同一确认人可连续确认；时间不足、确认人就是清洗人都会被拒绝。
   - 两次合格后结论为「准予回用」，进入待涂布队列。
4. **占用涂布槽**：仅「准予回用」可占用三个涂布槽之一；同槽互斥；涂布完成后释放。
5. **玻璃板档案更正 / 旧底片状态回退**：
   - 都会让当前回用结论**失效重算**，结论轮次（epoch）前进；
   - 旧检验/确认记录**归档留档**（履历页可展开查看），不物理删除；
   - 档案更正保留检验事实、确认必须重做；回退后需重新登记交付。
6. **重复或并发请求**：建档按编号去重；所有写动作支持 `requestId` 幂等键，重复或并发提交**沿用首次结果**。

## 代码结构（三个业务文件 + 薄路由）

| 文件 | 职责 |
| --- | --- |
| `rules.js` | 业务规则：状态机、缺陷准入、四小时确认、结论重算、归档、统一快照（列表/队列/履历同口径） |
| `records.js` | 记录与持久化：JSON 落盘、写操作链式串行、`requestId` 幂等、种子数据 |
| `page.js` | 页面：玻璃板列表、待涂布队列、玻璃板履历三个视图，均取自同一份 `/api/state` 快照，刷新后一致 |
| `server.js` | HTTP 薄路由，把动作转发给记录层 |

## 接口

- `GET /api/state` — 玻璃板列表、待涂布队列、活跃涂布槽、履历流水、归档、统计
- `POST /api/plates` — 建档（`code` 必填，重复编号沿用首次结果）
- `POST /api/plates/:code/delivery` — 旧底片交付登记
- `POST /api/plates/:code/confirm` — 表面洁净确认
- `POST /api/plates/:code/rollback` — 旧底片状态回退
- `POST /api/plates/:code/correct` — 玻璃板档案更正（`plateSize`/`source`/`note`）
- `POST /api/plates/:code/occupy` — 占用涂布槽
- `POST /api/plates/:code/complete-coating` — 完成涂布并释放槽位

写接口可在 JSON 中传 `requestId` 实现幂等，传 `at`（ISO 时间）可指定业务时间（测试/补录用）。
